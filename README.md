# CornerGrocer
1. Summarize the project and what problem it was solving.
  For this project, I created a C++ program for Corner Grocer to track how often customers purchased certain items. The problem was that the store needed a way to understand which products were being purchased the most without having to manually count everything. My program reads the purchase records from a text file and allows the user to search for a specific item, display how many times each item was purchased, or view the results in a histogram. It also creates a backup file containing the purchase counts.

2. What did you do particularly well?
  I think I did well with organizing my code and making the program easy to use. Instead of putting everything into one file, I separated the program into different files based on their purpose. I also used a map to store the items and their purchase counts. Another thing I did well was making the program recognize item names regardless of capitalization. This prevents the same item from being counted separately just because it was written differently.

3. Where could you enhance your code? How would these improvements make your code more efficient, secure, and so on?
  One improvement I could make is allowing the program to handle more types of input files. Right now, it expects each item to be a single word. I could change that so it can also read products with multiple words in their names. I could also improve how the program handles errors by providing more information when something goes wrong with a file. Another improvement would be using an unordered_map if I were working with much larger amounts of data, although I would need to sort the results separately. These changes would make the program more flexible and help it handle larger amounts of information.

4. Which pieces of the code did you find most challenging to write, and how did you overcome this? What tools or resources are you adding to your support network?
  One of the more challenging parts was handling the information from the text file and making sure each item was counted correctly. I had to understand how to read the file, store the information, and retrieve it when the user selected an option. Making sure the program could handle invalid menu inputs was another part that required attention. Breaking the program into smaller functions made it easier to understand what each part was doing. Visual Studio was useful for writing and checking the code. I also want to continue using course materials and C++ documentation when I come across something I don't understand.

5. What skills from this project will be particularly transferable to other projects or course work? 
  The skills I learned from this project that I can use in other projects are file handling, using maps, creating functions, and organizing code into separate files. I also got more practice with classes and working with user input. These skills can be useful in other programs that need to collect, organize, and display information. I think learning how to break a problem into smaller parts is one of the most useful things I can take from this project because it makes larger projects easier to approach.

6. How did you make this program maintainable, readable, and adaptable?
  I made my program easier to maintain by separating the main program from the GroceryTracker class. The main file handles the menu and user interaction, while the GroceryTracker class handles reading files, counting items, and displaying the results. I also used descriptive function names and comments to explain what certain parts of the code do. This makes it easier to understand the program without having to go through every line to figure out its purpose. If I wanted to add another feature later, I could make changes to a specific part of the program instead of having to rewrite everything.
